# Frontier — the 0.41.0 plan

The mining pass over a public interview-and-discipline skill library (credited in the
README's Sources section) and its repo-level doctrine: what the skills here adopt, what
the repository's infrastructure adopts, and what is explicitly left behind. The plan was
mined in two scouting passes (all 39 donor skills, its docs tree, side files, and the
out-of-scope ledger); everything below is written from scratch — no donor text ships.

The donor's own doctrine this plan does NOT adopt is recorded in
[docs/not-adopted.md](../not-adopted.md) alongside the older rejections this pass
re-confirmed.

## Wave 1 — the gates (existing skills)

| Skill | What lands |
|---|---|
| brainstorm | The **frontier**: after each round, recompute the set of questions whose prerequisites are settled and ask all of it; every question carries `➡️ recommended answer` phrased so "yes" accepts it; facts are found by the agent (recon, scouts), decisions are the user's; the interview ends when the frontier is empty — nothing silently assumed. The question budget (≤10/round, ≤3 blocking) stays — the donor argues against limits, this repo's budget is measured (0.39.0) and enforced by check-criteria |
| root-cause | The loop gate: one named command, already run at least once, red-capable on the user's exact symptom, deterministic, fast, agent-runnable — **no red-capable command, no diagnosis** (the anti-anchor rule); tighten the loop (faster / sharper signal / more deterministic); 3–5 ranked falsifiable hypotheses *before* testing any; minimize until every remaining element is load-bearing; `[DEBUG-xxxx]`-tagged instrumentation so cleanup is one grep |
| implementation-plan | Declared blocking edges (`- Blocked by:`) worked as a frontier; slices demoable on their own; task size = one fresh context window of work; **expand–contract** for wide refactors (add beside → migrate in batches → delete; "make the change easy, then make the easy change"); the brief contract — steps name behavior, not `file:line` (paths go stale; the Files line stays mechanical scope) |
| test-design | The expected value is an **independent literal** — never recomputed by the algorithm under test (a self-deriving test passes by construction); mock at system boundaries only, never what the repository owns; the dependency category decides the grader strategy (in-process / local-substitutable / remote-but-owned / true external); a red-test candidate is confirmed to fail **at the commit the executor starts from** |
| spec-review | Sharpened "a green run is not evidence": the assertion's expectation must be an independent literal against the criterion's words |
| scouts | Primary sources ("follow every claim back to the source that owns it"); shared exploration notes live outside the repository — pointers travel, not pastes; a belief reported as fact becomes a false premise — hypotheses until re-verified, sharper |
| defect-triage | Redundancy by **domain concept**, not wording; verification before questions (what the code at the named SHA can answer is answered, not asked); the needs-info ask carries "what we've established so far / what we still need"; wontfix splits three ways — already-implemented (cite where it lives, never filed as a rejection), rejected bug (a durable reason), rejected enhancement (the concept lands in docs/not-adopted.md); a resolved question is never re-asked |
| code-review | "Commit first, then review": a branch diff does not see staged work — a reviewer reading a working tree reviews what nobody asked to accept |
| spec-implementation | Merge evidence in the final report: the exact test that failed before and passes after (execution evidence > screenshot > prose); the one-way/two-way door line with the blast radius named |
| system-thinking | A decision record may be one paragraph; two qualifications earn a record without alternatives considered: **deliberate deviations** from the obvious path (the record stops the next reader from "fixing" the deliberate) and **constraints not visible in the code** |

## Wave 2 — doctrine and infrastructure

1. **CODESTYLE §11 "Writing for agents"** — the vocabulary: the two loads (context load
   vs cognitive load; the human is the index); the disclosure ladder (in-file step /
   in-file reference / disclosed reference — the branching test decides what goes behind
   a pointer); completion criteria carry clarity *and* demand ("every modified model
   accounted for" forces work "produce a change list" does not); prompt the positive —
   a prohibition drags the forbidden behavior into context, so steering leads with the
   desired action and blocks name the way forward; the no-op test — a line that does not
   change what the executor does is deleted, settled by running the document, not by
   debate. tech-writer is the scribe.
2. **CODESTYLE §6** — the observed-failure bar joins the clean room: a new skill clears
   the bar with an observed failure of a real session ("what you ran, what it did, what
   you expected"); "it would be better if" does not clear it; behavior composable from
   existing skills does not get a new skill.
3. **docs/not-adopted.md** — the durable why-not ledger: one row per concept, reasons
   that stay true ("we're busy now" is a deferral and stays open instead), already-built
   behavior never filed as a rejection, dedup by concept. Seeded from every mining pass
   to date.
4. **compliance.mjs gains two checks** — the router cannot lie: dispatch references no
   skill outside the roles map and names every role-entry skill; and every skill that
   dispatches subagents (mentions the scouts protocol) carries the fresh-context rule.
   (The donor's check-frontmatter gate is a duplicate here — compliance's strict YAML
   subset already parses frontmatter for exactly the host-rejection class.)
5. **skill-template + README** — the optional "It's working if" section: observable
   success criteria with failure tells ("if the theory arrives before the red command,
   the skill is not running").

## Wave 3 — the new surface

1. **`retro`** — the one new skill (shared): a session's retrospective that improves the
   **agent's environment**, not the code. Mechanical friction → a deterministic check
   (build-first: a check the repo runs beats a rule the agent must remember); judgement
   friction → a CODESTYLE rule (through codestyle); an existing-but-unwired check is the
   finding, not a reinvention; the no-op hunt; standards are imposed by the review side
   (least context pressure), not the implementation side. The clean room + the
   false-positive audit apply in full.
2. **brainstorm** — the prototype escape hatch (a decision that resists prose gets a
   throwaway artifact on a throwaway branch; the spec records the verdict and links the
   branch) and the fog rule (spec the settled part; ticket a question when it can be
   stated precisely now, not when it can be answered). Both sections, not skills — the
   spec chain in `docs/specs/` is already the cross-session state, so the donor's
   multi-session map and its session-handoff doc are not adopted (see not-adopted).

## Wave 4 — release

Tests for the two compliance checks; `retro` in the roles map (shared); docs parity
(docs/skills.md, the README counter 25 → 26, skill-index); version 0.41.0 in every
manifest; full `npm test`; the clean-room run of `retro` recorded; the release is
merged to main and tagged per the standing flow.

The clean-room run (a fresh session seeing only retro's SKILL.md, a scratch folder
outside the repository, a real retro task — a working session with five friction
items) **passed**: the report opened with the previous-retro check (honestly marked
unverifiable without repository access), every candidate named the friction and not
the fix, the unwired linter led the table (unwired checks come first), all five sorted
mechanical — with the reasoning that a remembered rule is exactly what the no-op
steering line proves does not work — the no-op was settled by the behavior comparison
the skill prescribes, the framework-carried question was answered per candidate, and
the run stopped at the proposal table: nothing wired, nothing committed. The
false-positive audit produced zero known-false-positives entries: every proposal is
actionable; one is noted as right signal, wrong weight (the docs-only suite fast path
— a senior might carry it as a convention instead of a new config option). The list
starts empty and grows from measurement.

## Wave 5 — the second pass over four donors

The same four sources re-mined with residual lenses (each first pass had been limited
to one aspect) folded into this release before it ships. The plan-of-record items:

1. **root-cause** — the three-failed-fixes breaker (repeated failure that reveals new
   coupling is wrong architecture, taken to the user), boundary instrumentation before
   any fix in multi-component systems, the defense-in-depth closing phase ("we made the
   bug impossible"), the ordered loop-construction catalogue, the seam exception.
2. **test-design** — the mutation check, the change-detector ban, assert-behavior-not-
   text, name-the-production-change-first, condition-based waiting (sleeps only for
   timing-under-test).
3. **spec-implementation** — the receiving-findings section: verify before implementing,
   unclear-stops-all, no performative agreement, the YAGNI grep, one-round pushback.
4. **code-review** — spec-silence grading ("a spec's silence is not permission") and the
   set-aside inventory; **spec-review** — run-over-run verdict deltas, the clarification
   journal, completion-claims-are-not-evidence, the glossary upkeep rules.
5. **brainstorm** — Must-not on every must criterion, TBD-with-validation-method,
   numbered replies, the Assumptions ledger, the builder check before saving, the
   glossary format rules.
6. **The self-owned escape hatch, fixed in the hook**: a plan authorizes code edits only
   with `status: approved` in its frontmatter (spec-gate); a draft plan gates every code
   edit; the status flip is a boundary note (edit-guard); plan-context names the state.
   "Constraints and exemptions must never live in a file the constrained agent writes."
7. **implementation-plan** — the capture rule, single-dominant-risk in the quiz, the
   builder check, the buildable-work coverage filter; **dispatch** — the ordered
   boundary tree (Continue → clear → subagent → compact-with-instruction, primary →
   secondary); **scouts** — preflight before the first dispatch; **defect-triage** —
   bulk-listings are not evidence, the AI-generated disclaimer line on draft replies;
   **retro** — the navigation/access/tooling categories and check-pruning; **system-
   thinking** — a deviation names the simpler alternative it beat; **trace-audit** —
   dead-citation walk check (a plan Source §N resolves to a numbered heading), the
   citation-or-dropped rule; **CODESTYLE §12** — the skill-authoring doctrine (baseline
   first, form-matching, no nuance clauses, regex→automate, self-evaluation is not
   evidence). The recheck's rejections join docs/not-adopted.md.
